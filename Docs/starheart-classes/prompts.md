# Series 12: Starheart Classes (prompt series)

Ten first-pass classes that mimic Starfinder 2e (and some 1e) classes: Envoy, Mystic, Operative, Solarian, Soldier, Witchwarper, Mechanic, Technomancer, Biohacker, Aspis Sleeper. Source draft: `source-v0.md` (owner's file, ~4,965 words, never edited).

Goals, in order: (1) grammar, spelling, internal consistency; (2) cut words, using the core classes as the baseline; (3) compare complexity with core: slightly more complex, not a new game; (4) compare power with core: slightly stronger, short of 1.5x damage per round; (5) a theme-breaking pass on domain cards for each class.

## Rules for every prompt
- Files live in `Docs/starheart-classes/`. Versions are separate files and each prompt reads the last one and writes the next: `source-v0.md` (original) -> `v1-clean.md` (prompts 2-3) -> `v2-reduced.md` (4-5) -> `v3-tuned.md` (6-8) -> `v4-final.md` (9-10). Reports go in `reports/`.
- Rules text only (memory `rules-text-only`): no flavor in the class text. Keep the owner's names, terms and numbers unless a change is listed for the owner to approve.
- Mechanics changes are proposed, not applied, unless the draft is plainly self-contradictory. Typos and grammar are just fixed. Each prompt ends with a short numbered decision list, each item yes/no or lettered, so the reply can be "3. A".
- Word and feature counts come from the script built in prompt 1 (same counting rule every time). Do not hand-count.
- At the end of each prompt: mark it done in `Docs/plan.md` (Series 12), update `start-here.md`, say what the owner can look at and what is unchecked. No commits until the series is finished and the owner asks.
- Owner decisions (2026-10-26): budget is core mean x 1.15 (class level 160 words / 3.5 features; one subclass 185 / 5; ranks 65 / 55 / 60 words; whole class 525 words; variance allowance: up to two classes may run to 630 words, the rest stay at or under 525, the owner picks which two, and the allowance is for words only, features still aim at about 14); cuts mainly merge or drop features, aiming at 4-5 per subclass and about 14 per class; **every proposed change that is more than a typo or punctuation fix is shown to the owner as one batch per class** (a numbered, lettered list for that class: before text, after text, why) and applied only after the owner answers. In prompts 2-5 that means one batch for each of the five classes in the prompt, so the prompt stops after the batches and applies the answers at the start of the next prompt.
- Out of scope (goes to `long-term-to-do.md`): turning these into a source pack, wizard/level-up/sheet support, Tier 2+ class cards, equipment.

## Prompt 1. Baseline and intake
Read `start-here.md`, `Docs/starheart-classes/prompts.md` and `source-v0.md`. Build `scripts/starheart-metrics.mjs`, which counts words and named features for any class markdown (`source-v0`, later versions) and for the 13 core classes from `packs/core/srd-core.json` (use `rules`, not `short`). Count class-level features (hope feature + class features) and each subclass by rank (foundation, specialization, mastery) separately. Write `reports/baseline.md`: per-core-class and per-Starheart-class tables, core mean / median / max, and a proposed word and feature budget per class and per subclass rank for the Starheart classes (a little above core, since the goal is slightly more complex). Also list every structural oddity in the draft you see (a first read already shows: empty Aspis Sleeper Hope Feature, a feature named "XXX", missing Stress on Soldier, no Spellcast trait on Soldier subclasses, duplicate Machine Whisperer text in Mechanic and Technomancer, inconsistent rank headings, subclasses with more or fewer features than core). Do not edit the draft. Ask the owner to approve the budget.

## Prompt 2. Grammar and consistency, part A
Classes: Envoy, Mystic, Operative, Solarian, Soldier. Write them into `v1-clean.md` (create it with these five; B appends the rest). Fix spelling, grammar, punctuation, capitalization. Normalize terms against the core rules text (Hope, Fear, Stress, HP, Armor Slot, spotlight, Tier, Evasion, trait names, range names, "action roll", "reaction roll", "Spellcast" vs "Spellcasting"). Normalize stat-line format and heading format to the core pattern. Check internal consistency: every term, token, pool and condition is defined before use or in the core rules (Envoy Tokens, Vitality Points, Mystic Bond, tag team, Solar Conjuration, Suppressed, Primary Target, Quantum Field...), numbers agree, "this" and "that" references land, nothing is both required and forbidden. Output `reports/consistency-A.md`: every change in a compact table, plus a "needs owner" list (questions, not fixes).

## Prompt 3. Grammar and consistency, part B
Classes: Witchwarper, Mechanic, Technomancer, Biohacker, Aspis Sleeper. Same procedure; append to `v1-clean.md`. Then a cross-class pass over all ten: shared terms used the same way (Tech damage, tokens, "forgo", "reaction", Sidekick), duplicated text (Machine Whisperer) either shared by reference or deliberately different, domain pairs listed correctly, each class has a Spellcast trait where it needs one. Output `reports/consistency-B.md` and a merged numbered decision list from parts A and B (owner answers, then Claude applies the answers to `v1-clean.md` at the start of prompt 4).

## Prompt 4. Word-count reduction, part A
Apply the prompt 2-3 decisions to `v1-clean.md`. Then, for Envoy, Mystic, Operative, Solarian, Soldier, cut words toward the approved budget without changing mechanics: drop filler, examples, repeated definitions, "you may" padding; fold features that are one idea; use the core classes' phrasing. Where a cut would change a mechanic, do not cut; list it instead. Write `v2-reduced.md` (these five). Output `reports/words-A.md`: before/after words and feature counts per class and per subclass rank against baseline, and a list of features proposed for merging or removal with the reason.

## Prompt 5. Word-count reduction, part B
Same for Witchwarper, Mechanic, Technomancer, Biohacker, Aspis Sleeper; append to `v2-reduced.md`. Output `reports/words-B.md`. Close with a combined table of all ten against the budget and a decision list covering merge/remove proposals from A and B.

## Prompt 6. Complexity comparison
Apply the prompt 4-5 decisions. For every class (v2), count moving parts against core: new resources or trackers, modes or states, conditions invented, per-turn or per-rest triggers, rules that edit other rules (Tech Savvy, Dread Abilities, Machine Whisperer), extra tables or lists, and "must remember mid-turn" items. Compare to core mean and max from the baseline. Target: slightly above core, not a new game. Output `reports/complexity.md`: a per-class score with the parts listed, a flag for each class well above target (and which parts to simplify) and each well below (where it could carry more). Propose the specific changes as a numbered decision list. Apply the approved ones to start `v3-tuned.md` (all ten classes) at the start of prompt 7.

## Prompt 7. Power: model and first five classes
Apply the prompt 6 decisions into `v3-tuned.md`. First write `reports/power-model.md`: a damage-per-round model for a core baseline (primary weapon at proficiency per tier, hit chance against typical difficulty, crit rate, Hope spent per round, a typical core class damage feature) and the assumptions, including how to count ally buffs and conditional damage (Envoy Focus Fire, Called Shot, Solar Weapon, Suppression, etc.) as party damage contribution. Ceiling: below 1.5x core per round; flag anything over about 1.3x. Stop and get owner OK on the assumptions only if they are contested (list them as a short decision list); otherwise proceed. Then run the model (a script in `scripts/`, results in `reports/power-data.csv`) for Envoy, Mystic, Operative, Solarian, Soldier at Tiers 1 and 2 and report. Non-damage output (healing, control, utility) is listed qualitatively, not converted into damage.

## Prompt 8. Power: remaining classes and tuning
Same model for Witchwarper, Mechanic, Technomancer, Biohacker, Aspis Sleeper. Combined table of all ten: DPR ratio to core, plus notable non-damage power (burst turns, once-per-session spikes, free actions, stacking). Propose numeric tuning only for outliers (over 1.3x, or far below 1.0x), as a numbered decision list. Apply approved changes into `v3-tuned.md`; re-run the metrics script and the model to confirm every class is inside the target band, and report words and complexity again so the tuning did not undo prompts 4-6.

## Prompt 9. Theme-breaking cards, part A
Classes: Envoy (Grace, Bone), Mystic (Arcana, Splendor), Operative (Midnight, Codex), Solarian (Blade, Arcana), Soldier (Valor, Dread). From `packs/core/srd-core.json`, read every card in each class's two domains (rules text). Flag cards that break the Starfinder theme (fantasy creatures, gods, swords-and-sorcery imagery, nature magic, undead, spellbooks and incantations) and say why. For each flagged card choose one fix: (a) explain-away via the class's existing reskin text ("Tech", "Kit"), (b) a one-line reskin note, (c) swap in a replacement or ban the card, with a proposal. Domains shared across classes are analyzed once and reused. Output `reports/theme-A.md` (per class: counts, flagged cards, proposed fix). End with the owner decision list (lettered).

## Prompt 10. Theme-breaking cards, part B and final
Classes: Witchwarper (Dread, Midnight), Mechanic (Valor, Sage), Technomancer (Codex, Sage), Biohacker (Bone, Splendor), Aspis Sleeper (Blade, Grace). Same procedure, reusing domain results from prompt 9. Then apply all approved theme decisions to `v3-tuned.md` -> `v4-final.md`, run the metrics script a last time, and write `reports/summary.md`: final words, features, complexity and power against core for all ten, plus the unresolved items. Update the long-term list (source pack and wizard support, Tier 2+ cards, equipment). Mark the series done in `Docs/plan.md` and `start-here.md`; the owner decides when to archive it and commit.
